\para{One machine and one readout}
Fix Mathlib's partial-recursive universal evaluator. Compilation through its stack and tape machines, then restriction to its finite program support, gives one tape table for every $p,x$. To preserve every binary string, including trailing zeros, append a final $1$ before interpreting the string in binary, low bit first. For each $f$, the library supplies a program for this coded function. The seed writes the reversed input and program bits with three fixed tape symbols, then wraps the initial tape in fixed-width blocks.
A bottom-up pass marks passing subtrees. One descent selects the first passing packet in preorder. A finite-state transducer copies the final row from its word. Unfolding the two tape tracks, projecting the main stack, reversing its digits and dropping the final $1$ returns $y$. Every passing packet gives the same $y$. These are fixed linear passes on the expanded tree and row. To test any regular property of $y$, each segment need only store its action on the finitely many states of the output automaton. This also handles reversed segments and yields the regular preimage in the theorem.
